# 需求规格说明书

> 项目名称：基于特征工程与 LSTM 的设备故障 PHM 预测系统
> 版本：V1.0　日期：2026-09-11

## 1. 引言

### 1.1 编写目的
明确系统的功能与非功能需求，作为设计、开发、测试与验收的依据。

### 1.2 项目背景
设备意外停机造成重大经济损失，预测性维护（PHM）通过传感器数据预测设备剩余使用寿命（RUL），实现从"故障维修"到"状态维修"的转变。本系统以 NASA C-MAPSS 涡扇发动机退化数据为对象，构建 RUL 预测 Web 系统，方法可推广至机床、风机等通用工业设备。

### 1.3 术语
- PHM：Prognostics and Health Management，故障预测与健康管理
- RUL：Remaining Useful Life，剩余使用寿命
- 飞行循环：发动机一次起降运行周期，本系统的时间单位

## 2. 总体描述

### 2.1 系统定位
面向制造/工业设备运维场景的 B/S 架构智能应用：上传传感器监测数据 → 预测剩余寿命 → 健康评估 → 维护建议 → 历史记录。

### 2.2 用户与目标
| 用户 | 使用目标 |
|---|---|
| 设备维护工程师 | 获取 RUL 预测与健康等级，制定维护计划 |
| 生产管理者 | 掌握设备健康趋势与风险概况 |

### 2.3 运行环境
- 服务端：Windows / Linux，Python 3.10+，CPU 即可运行
- 客户端：现代浏览器（Chrome / Edge）

## 3. 功能需求

### FR1 数据上传
- 输入：传感器时序文件（CSV/TXT），支持 C-MAPSS 26 列格式与带表头 CSV；
- 约束：文件非空；缺失选定传感器列时按 0 填充。

### FR2 RUL 预测
- 输入：单台设备最近若干飞行循环的传感器数据；
- 处理：传感器筛选 → 滑动窗口（30 循环）→ 归一化 → LSTM 推理；
- 输出：RUL 预测值（飞行循环，精确到 0.01）。

### FR3 健康状态评估
- 依据 LSTM 预测 RUL 映射健康等级：
  - RUL > 100：健康；50 < RUL ≤ 100：退化；
  - 20 < RUL ≤ 50：危险；RUL ≤ 20：失效风险；
- 输出对应维护建议文本。

### FR4 基线对照
- 输出随机森林基线模型的 RUL 预测，与 LSTM 结果并列展示。

### FR5 趋势可视化
- 展示最近窗口内选定传感器（至多 6 个）的原始值趋势折线图。

### FR6 历史记录
- 预测记录持久化至 SQLite（时间、设备、已用循环、LSTM RUL、RF RUL、健康等级、建议）；
- 支持按时间倒序查询最近 50 条。

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR1 | 性能 | 单次预测响应 < 3 秒（CPU 推理） |
| NFR2 | 正确性 | 特征工程/模型/接口自动化测试全部通过 |
| NFR3 | 可用性 | 一键启动（start.bat），本地浏览器访问 |
| NFR4 | 可追溯 | git 小步提交；AI 对话记录存于 prompt/ |
| NFR5 | 可复现 | 数据→预处理→训练→预测全流程脚本化 |

## 5. 数据需求

- 训练数据：NASA C-MAPSS FD001（100 台发动机，20631 条记录）；
- 数据格式与预处理详见 `data/说明.md`；
- 模型输入：窗口 30 循环 × 选定传感器（约 14 个）归一化序列。

## 6. 接口需求

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | /health | - | {status, service} |
| POST | /api/predict | multipart: file, unit_id? | 预测结果 JSON（含 trend） |
| GET | /api/history | limit | 预测记录数组 |
| GET | /api/units | limit | 训练单元信息数组 |
| GET | / | - | 前端页面 |

## 7. 验收标准

1. 上传 `data/sample_upload.csv` 可完成预测并展示结果与图表；
2. 预测记录写入数据库并可查询；
3. `pytest tests/` 全部通过；
4. 一键启动脚本可用，浏览器访问 8000 端口正常。
