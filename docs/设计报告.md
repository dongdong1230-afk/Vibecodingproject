# 面向离散制造业产品BOM智能解析与物料替代方案推理B/S系统 —— 课程设计报告

（封面信息：课程名称《制造智能技术》、题目、姓名学号班级、指导教师、日期）

## 1 背景调研（研究意义）

产品 BOM（物料清单）是离散制造企业的核心基础数据，贯穿设计、采购、生产、成本核算全流程。
实际运营中三类物料问题高发：**停产（EOL/phase-out）**——供应商产品迭代导致的不可采购；
**缺货**——库存低于安全库存导致的生产线停线风险；**交期超期**——进口件长交期拉长生产周期。

传统处理方式依赖 BOM 工程师人工查找替代物料，存在明显痛点：①效率低——翻目录、查手册、
比参数耗时长；②对比维度少——往往只比较价格与交期，忽略性能覆盖与工艺兼容约束；
③经验难复用——历史替换案例散落在个人记忆中，重复踩坑；④方案可靠性差——缺乏量化评估，
替代后质量风险高。

课题意义：借助制造智能技术自动解析 BOM 结构、按规则识别风险物料、以本体推理保证替代物料
的硬约束合规、以案例推理复用历史验证经验、以模糊综合评价多维度量化打分，辅助工程师快速
完成可靠物料替换，降低物料变更带来的质量与供应风险。场景为离散制造企业 BOM 维护/工艺物料
选型环节，属于真实工业业务场景（本课题调研阶段检索了公开 BOM 数据集与物料分类标准，
见 3.2 节数据来源）。

## 2 方案设计

### 2.1 技术方向映射（对应课程章节）

| 技术方向 | 系统模块 | 业务作用（非装饰） |
|---|---|---|
| 本体与知识推理 | 物料替代本体 + 规则引擎 | 推理"哪些物料可替代"：三级硬约束过滤输出合规候选集 |
| 案例推理 CBR | 历史变更案例库 + 加权 kNN | 检索"哪些替换被历史验证"：复用成功案例、警示失败案例 |
| 模糊综合评价 FCE | 五指标隶属度 + AHP/熵权 + 模糊合成 | 判定"哪套方案最优"：多方案打分排序 |

### 2.2 总体架构

B/S 架构（架构图见 README）：前端 Vue3 免构建 SPA（6 页面）；后端 FastAPI 分层
（routers → services → db）；SQLite 8 张业务表；知识配置 JSON 化（本体/风险规则/FCE 配置），
算法三模块从零轻量实现（不依赖 owlready2/sklearn 等重型框架），离线可运行。

### 2.3 三模块算法设计

**模块 1 本体与知识推理**
- 本体要素：类别层级（4 大类 15 中类 26 小类，51 个类别节点）、每小类性能参数 schema
  （key/类型/覆盖方向：gte/lte/equal 容差/allow_map 封装升级映射）、禁止替代对 12 对
  （如铝电解↔钽电容、步进↔伺服电机）、显式替代规则 9 条（同小类、工况规则、质量底线）。
- 与标准本体语言对应（meta.owl_mapping_note 与规则 swrl 字段）：
  类别层级↔OWL 类公理(subClassOf)；属性 schema↔DataProperty 定义域/值域；
  规则↔SWRL；禁止对↔负向断言；物料实例↔ABox 个体。
- 推理流程：同小类倒排索引取候选 → L2 参数覆盖逐属性检查（任一硬属性不满足即剔除）
  → L3 显式规则（rule_engine 求值）+ 禁止对 + 工况约束 → 输出候选集，每候选带
  命中规则列表与可读推理路径（如"同小类[R-CAT-01]✓ → 额定功率 0.125≥0.1[R-PARAM-power_w]✓
  → 封装 0603→0805 允许映射✓"）。
- 支持导出 ontology.cypher（Neo4j 一键导入，含 CAN_SUBSTITUTE 边）。

**模块 2 CBR 案例推理**
- 案例结构：旧/新物料、产品工况（温度/电压/环境）、变更原因、变更后效果（success/partial/failed）
  及量化指标（故障率、成本变化率、交期）。
- 相似度：sim_cat 类别层级相似度（归一化 Wu-Palmer：同小类=1.0/同中类=0.667/同大类=0.333）
  ×0.30 + sim_param 参数相对容差（1-min(1,|x-y|/(0.25|y|+ε))）×0.40 + sim_cond 工况匹配
  （0.4×产品大类+0.4×工况字段等级匹配（相邻=0.5）+0.2×变更原因）×0.30；
  效果加权 score_eff = score×{success:1.0, partial:0.8, failed:0.5}。
- 检索策略：同中类预筛 → 可复用组（非失败且 score_eff≥0.60，top-5）→ 失败警示组
  （失败案例按原始相似度≥0.60 展示，避免效果降权掩盖高危警示）。

**模块 3 FCE 模糊综合评价**
- 指标集 U：性能匹配度、工艺兼容性（本体软评分——参数裕度与类别属性映射距离量化）、
  采购成本、供货交期、历史故障率。
- 隶属度：评语集 V={优,良,中,差}，分值 [100,80,60,40]；半梯形+三角形隶属函数
  （μ优=trapmf(0.7,0.85,1,1) 等），四级隶属度和≈1（单测断言）。
- 权重：AHP 判断矩阵（特征向量法幂迭代 + 一致性检验 CR=0.015<0.1）× 熵权法
  （指标差异自适应）乘法合成归一化；三种模式可切换。
- 合成：加权平均型 M(·,+)（保留全部信息，优于主因素决定型 M(∧,∨)）；
  得分 S=Σb_j·c_j 百分制，等级按最大隶属度；并列时成本低者优先。
- 业务细节：停产/将停产的**原物料不参与排序**（不可再采购，仅作对比基准）。

## 3 数据资源构建

### 3.1 数据流程
`seed_all.py` 一键重建：generate_ontology → generate_materials（688 物料）→
generate_boms（8 产品 3~4 层 BOM）→ generate_cases（100 案例）→ SQLite 入库。

### 3.2 数据来源（如实披露）
公开的"真实企业级 BOM 数据集"几乎不存在（BOM 属企业核心数据），本课题数据为
**脚本生成的仿真数据**（seed=42 固定，可复现），风格参考公开来源：
- BOM 字段结构：Kaggle Engineering Blueprints & BOM Dataset；
- 物料件号编码体系：Octopart Common Parts Library（"类别-关键参数-规格"编码，
  以及"每个通用件多个可订购替代型号"的替代料思想）；
- 类别层级组织：IOF Core 工业本体、ECLASS 分类思想；
- 产品 BOM 结构：典型工业控制/电力电子设备公开资料（智能电表、变频器、AGV 驱动器等）。

### 3.3 仿真数据设计要点（保证演示闭环）
- **替代链保证**：同小类物料按"参数覆盖关系"确定性生成（如同阻值多封装多功率档、
  螺栓强度等级/表面处理向上兼容映射），使风险物料必有合规替代候选；风险植入
  （EOL 12%/phaseout 8%/缺货 12%/长交期）优先挑选"有替代候选"的物料，避免死端。
- **案例与本体同源**：案例新物料经本体 property_schema 覆盖检查验证合规，
  保证 CBR 推荐与本体推理不冲突。
- **刻意植入**：钽电容缺货、进口轴承长交期（NSK/SKF 30~45 天）、EOL 电阻/步进电机等，
  形成完整演示场景；高温/潮湿/振动工况产品用于触发工况规则（如高温 X5R 禁止替代 X7R、
  潮湿环境镀锌螺栓不可替代达克罗处理件）。

## 4 系统实现

### 4.1 后端（FastAPI + SQLAlchemy）
- 分层：routers（7 个，30 个端点）→ services（7 个业务/算法服务）→ db（8 表）。
- 8 张表：materials 物料主数据（本体 ABox）；bom_products/bom_lines 产品与 BOM 行
  （层级/父件/用量/路径）；risk_records 风险记录（判定明细 JSON 可解释）；
  bom_change_cases 案例库；substitution_plans 方案（含本体规则命中/CBR 案例 ID/FCE 得分）；
  plan_scores FCE 指标明细；bom_versions 版本快照（回溯数据源）。
- 关键服务：
  - bom_service：导入解析（pandas/openpyxl，列名别名映射、层级推导、路径构建）、
    结构树（自底向上用量汇总）、版本管理（快照/回滚）；
  - rule_engine：JSON 规则表达式求值器（无 eval，支持 ref/比较/and/or/not/mul，
    路径缺失安全），风险判定与本体规则共用；
  - substitution_service：三模块编排（本体候选 ∪ CBR 复用（经本体硬约束过滤）→ FCE
    排序 → 方案保存/应用/风险关闭）。

### 4.2 前端（Vue3 免构建 SPA）
- 6 页面：BOM 管理（导入/树/加行）、风险识别（扫描/明细/跳转）、替代推理（三栏：
  风险列表/本体候选卡片+CBR 案例卡/已选与 FCE 结果+雷达图）、方案对比（逐项对比+图表+
  应用）、方案历史（版本时间线+diff+回滚）、数据看板（统计卡片+4 类图表）。
- 公共组件：风险/级别/效果/状态标签、ECharts 容器（懒初始化：隐藏容器尺寸为 0 时
  不初始化，避免渲染管线异常）、属性对比表、候选卡/案例卡。
- 跨页上下文：风险页 → 替代推理页的"一键生成替代方案"通过根组件 subContext 传递，
  页面常驻（v-show）下以 watcher 消费（注册时机须在挂载完成后，详见 6.3 案例 7）。

### 4.3 数据库（SQLite）
8 张表关系：产品 1—N BOM 行；BOM 行 1—N 风险记录；方案 N—1 BOM 行；方案 1—N 评分明细；
产品 1—N 版本快照。DB_URL 可切 PostgreSQL；本体关系可经 ontology.cypher 导入 Neo4j。

## 6 AI 使用披露（Vibe Coding 过程档案）

### 6.1 所用工具
- **Claude Code（VSCode 扩展）**：全程主力编码助手（本课设全部代码经其生成/修改并
  人工审查、运行验证）。
- 配套工具：git（版本控制）、jsdom+playwright-core（前端测试与截图）、
  Python unittest（后端测试）、CDP（性能/卡死调试）。

### 6.2 关键 prompt 策略（提示词工程与上下文工程）
1. **规格驱动开发**：先让 AI 读选题说明与任务书 PDF，产出技术方向映射表与系统架构草图
   （方案设计.md），再按"每步可独立提交、可测试"的 15 个 git 里程碑推进，每里程碑以
   验收标准收口（如"单测 16 例全过"）。
2. **上下文工程**：编写 CLAUDE.md 项目规则（架构约定/提交规范/测试命令），让 AI 每次
   修改前先读参考项目（上一课设 keshe）的代码模式再动手；数据生成脚本与本体推理
   共用同一套 property_schema 覆盖逻辑，从源头保证"训练-推理"一致。
3. **验收标准先行**：每个算法模块先写单元测试清单（边界用例：=阈值不触发、50%/80%
   分档、隶属度和≈1、CR<0.1），再实现，倒逼实现正确性。
4. **数据质量验证脚本**：数据生成后运行独立验证脚本，检查"每个 BOM 风险物料必有合规
   替代候选""案例新物料必合规"，不合格即重构生成器。
5. **可解释性约束**：所有规则带中文名/SWRL 对应/推理路径文案，AI 生成的代码必须能
   讲清"为什么"（对应答辩随机代码段讲解要求）。

### 6.3 AI 出错案例及纠正过程（基于 prompt/ 会话日志，如实记录）
1. **PDF 提取乱码误判**：任务书 PDF 嵌入字体无 ToUnicode 映射，pypdf/pdfminer 提取
   输出看似乱码；经码点检查发现文本实际正确，乱码仅是 Windows 控制台编码显示问题。
   纠正：写文件后用 UTF-8 读取，不轻信终端显示。
2. **仿真数据"替代链断裂"**：初版生成器按随机组合生成物料，导致 32 个 BOM 风险物料
   无合规替代候选（如顶配 1206 电阻无升级空间、随机精度轴承无 P6/P5 链）。
   纠正：生成策略重构为"确定性替代链"（同阻值全封装档、强度/表面处理向上兼容映射），
   风险植入优先挑选有候选者，并增加候选数预计算过滤。
3. **物料编码重复**：连接器高度变体与螺母表面处理未进编码，导致 20 组编码冲突
   （SQLite UNIQUE 约束报错）。纠正：编码规则补全变体维度后重建。
4. **EOL 原物料在 FCE 中排名第一**：评估把原物料放入候选排序，"自己比自己"性能/工艺
   得分最高，停产物料反而"最优"。纠正：EOL/phaseout 原件不参与排序，仅作对比基准。
5. **CBR 推荐未过本体硬约束**：相似案例的替换物料（针对不同旧料）直接注入候选，
   出现外径不符的轴承候选。纠正：CBR 复用物料注入前经本体 check_coverage+禁止对+
   显式规则过滤，被过滤项前端标记"本体约束过滤"。
6. **遗漏 app.use(ElementPlus)**：全部 el-* 组件当原生元素渲染，模板插槽作用域解构报错。
   纠正：注册插件，挂载测试即刻暴露并修复。
7. **跨页上下文监听失效**：页面常驻（v-show）mounted 只执行一次；watcher 在挂载期间
   注册时 window.appRoot 尚未赋值（TDZ/无响应式依赖），监听永不触发。纠正：watcher
   改在异步回调（挂载完成后）注册，getter 直接读 window.appRoot.page。
8. **版本快照时机错误**：应用方案时先快照后更新行，新版本快照的是"变更前"状态，
   diff 恒为空。纠正：先更新 BOM 行再快照（版本链语义：v1=原始 → v2=替换后）。
9. **ECharts headless 死循环**（见 5.2）：先怀疑 echarts 文件损坏（换官方 5.5.1 无效），
   经 CDP 抓主线程栈定位渲染管线，最终确认是零尺寸容器初始化问题，懒初始化解决。

**体会**：AI 生成代码的错误集中在"边界条件与业务语义"而非语法——AI 能快速搭出框架，
但替代链完备性、版本快照语义、组件注册这类隐蔽问题必须靠自动化测试与真实环境运行暴露，
"测试先行 + 数据验证脚本 + 真实浏览器验证"是 vibe coding 流程中人工兜底的关键环节。

## 7 总结与展望

### 7.1 完成情况
系统实现了选题说明的全部目标：BOM 导入解析与结构树、三类风险识别、本体+CBR 双路替代推理、
FCE 五指标评估、方案保存/应用/版本回溯完整闭环；三个课程技术方向全部真实参与业务计算；
交付物齐全（git 15 个里程碑提交、README、需求规格说明书、设计报告、演示脚本、prompt 日志、
页面截图素材）；自动化测试 108 例全部通过（55 单测+37 e2e+16 挂载）。

### 7.2 展望
1. 本体层：接入标准 OWL 推理机（如 owlready2）与 Neo4j，替换 JSON+规则引擎以支撑更大
   规模知识库与复杂规则；
2. 案例库自增长：方案实际应用效果自动回写案例库（当前为手工录入接口），形成持续学习闭环；
3. 供应数据实时化：对接公开元器件 API（如 Nexar/Octopart 生命周期状态）替代仿真风险数据；
4. 批量优化：面向整机 BOM 的全局替换组合优化（多物料联合替换的成本最小化）。
