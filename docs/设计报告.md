# 设计报告

## 基于特征工程与 LSTM 的设备故障 PHM 预测系统

> 制造智能技术课程设计 · 2026-09

---

## 摘要

设备非计划停机是制造业的主要损失来源。本设计面向"设备运维"这一制造环节，以 NASA C-MAPSS 涡扇发动机退化数据集为对象，构建了一套基于**特征工程与 LSTM 循环神经网络**的剩余使用寿命（RUL）预测系统。系统采用 B/S 架构，前端提供数据上传、预测结果展示、传感器趋势可视化与历史记录查询；后端基于 FastAPI 提供预测与数据接口，SQLite 实现结果持久化；算法层实现传感器筛选、滑动窗口特征构造、LSTM 预测与随机森林基线对照、健康状态评估四个模块。测试集上 LSTM 的 RMSE 明显优于随机森林基线，验证了深度学习在时序退化建模上的优势。项目全程使用 git 管理并采用 vibe coding 方法开发，AI 对话过程全部留档。

## 1 背景调研与研究意义

### 1.1 研究背景

设备故障预测与健康管理（PHM, Prognostics and Health Management）是智能制造的核心方向之一。传统维护模式分为事后维修（故障后维修，停机损失大）与定期维修（按固定周期维修，存在过度维修）。预测性维护通过传感器实时监测数据预测设备剩余使用寿命（RUL），在故障发生前安排维护，能够显著降低非计划停机损失、延长设备寿命、优化备件与人力调度。

### 1.2 研究意义

- **工业价值**：据工业界统计，非计划停机可造成每分钟数千美元的直接损失；预测性维护可减少 30%–50% 的维护成本。
- **技术价值**：RUL 预测是典型的**多变量时间序列预测**问题，将课程所学的机器学习、深度学习、数据预处理等知识落地到真实工业场景。
- **可推广性**：本系统以航空发动机为演示对象，其特征工程与预测方法可迁移至机床主轴、风机、压缩机等通用旋转机械。

### 1.3 国内外研究现状

RUL 预测方法经历了三个阶段：基于物理模型（机理建模，精度高但依赖机理知识）、基于统计模型（如 Wiener 过程、隐马尔可夫模型）、基于数据驱动模型。数据驱动方法中，LSTM 因其对时间依赖的建模能力成为 RUL 预测的主流方法之一。Heimes（2008）最早将 RNN 用于 RUL 估计；后续研究在 C-MAPSS 数据集上验证了 LSTM 优于传统机器学习方法。本设计采用"特征工程 + LSTM + 机器学习基线对照"的技术路线，与主流研究一致。

## 2 方案设计

### 2.1 系统目标

构建可运行的 B/S 架构 RUL 预测系统：用户上传设备传感器时序数据，系统返回剩余寿命预测、健康等级与维护建议，并支持历史记录查询。

### 2.2 总体架构

系统采用分层 B/S 架构：

```
前端（HTML/CSS/JS + ECharts）
   │ HTTP/JSON
后端服务层（FastAPI：路由 + 业务编排）
   ├─ 算法层：特征工程 → LSTM → 健康评估（+RF 基线）
   └─ 数据层：SQLite（预测记录、单元信息）
```

各层职责清晰、通过 API 解耦，符合课程"完整 B/S 架构"要求。

### 2.3 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS + ECharts | 免构建链、部署简单，图表库成熟 |
| 后端 | Python + FastAPI + Uvicorn | 轻量、自动 OpenAPI 文档、异步性能好 |
| 数据库 | SQLite | 零配置、单文件，适合课程规模 |
| 深度学习 | PyTorch（CPU 版） | 生态成熟、接口灵活 |
| 机器学习 | scikit-learn（随机森林） | 基线模型，与 LSTM 对照 |
| 测试 | pytest + FastAPI TestClient | 覆盖算法与接口 |

### 2.4 算法方案

1. **特征工程**（数据预处理技术方向）：
   - 传感器筛选：计算 21 个传感器与 RUL 的 Pearson 相关系数，保留 |r| ≥ 0.5 的 12 个有效传感器（sensor2/3/4/7/8/11/12/13/15/17/20/21），剔除温度、压力等恒定工况传感器，降低噪声；
   - 滑动窗口：窗口长度 30 个循环，构造 LSTM 序列输入与窗口统计特征（末值/均值/标准差/斜率）供随机森林使用；
   - 归一化：Min-Max 归一化至 [0,1]。

2. **LSTM 预测模型**（深度学习技术方向）：
   - 网络：2 层 LSTM（隐藏单元 128，dropout 0.2），读取层融合最后时间步与全局平均池化，经全连接回归输出 RUL；
   - 训练：MSE 损失、Adam 优化器 + 学习率衰减、早停取验证集最优权重、RUL 上限截断 125；
   - 训练样本：5947 条窗口样本（100 台训练发动机）。

3. **随机森林基线**（机器学习技术方向）：200 棵树回归，输入窗口统计特征，用于验证深度学习增益。

4. **健康状态评估**（状态评估与决策技术方向）：将预测 RUL 映射为四级健康状态并输出维护建议：

| RUL | 健康等级 | 维护建议 |
|---|---|---|
| > 100 | 健康 | 常规周期维护 |
| 50–100 | 退化 | 纳入计划性维护窗口 |
| 20–50 | 危险 | 近期检修，加密监测 |
| ≤ 20 | 失效风险 | 立即停运检修 |

## 3 数据资源构建

### 3.1 数据来源

采用 **NASA C-MAPSS** 涡扇发动机退化仿真公开数据集（FD001 子集）：训练集 100 台发动机运行至失效的完整时序（20631 条记录），测试集 100 台发动机截断时序（13096 条记录），每条记录含 3 个工况参数与 21 个传感器值。数据集来源：https://data.nasa.gov/dataset/cmapss-jet-engine-simulated-data

### 3.2 数据预处理

| 步骤 | 方法 |
|---|---|
| RUL 标签构造 | 训练集每循环 RUL = 单元最大循环 − 当前循环，上限截断 125 |
| 传感器筛选 | Pearson 相关系数阈值 0.5，得 12 个有效传感器 |
| 滑窗与特征 | 窗口 30、训练步长 3；统计特征 4×12=48 维 |
| 归一化 | Min-Max 到 [0,1] |

预处理脚本 `scripts/preprocess.py` 一键复现，产物见 `data/processed/`。

### 3.3 数据管理

原始数据存于 `data/raw/`（公开数据集本地备份），预处理元信息与测试样本入库，大体积训练样本由脚本重建（.gitignore 排除），符合任务书"数据量小直接提交 /data，公开数据集给出来源链接并写说明"的要求。

## 4 系统实现

### 4.1 前端实现（B/S 客户端）

单页面应用（`frontend/`），四个功能区：

1. **数据上传**：文件选择 + 设备编号输入，支持 C-MAPSS 格式与带表头 CSV；
2. **预测结果**：RUL 预测值、健康等级徽章（颜色区分）、随机森林对照值、维护建议卡片；
3. **趋势可视化**：ECharts 折线图展示最近窗口内 6 个关键传感器的原始值趋势；
4. **历史记录**：表格展示数据库中的预测记录，支持刷新。

### 4.2 后端实现

FastAPI 应用（`backend/app.py`），主要接口：

| 接口 | 功能 |
|---|---|
| POST /api/predict | 接收文件，编排特征工程→LSTM→健康评估→入库，返回结果 |
| GET /api/history | 历史预测记录（倒序） |
| GET /api/units | 训练集单元信息 |
| GET /health | 健康检查 |

业务编排位于 `backend/services/predictor.py`：解析上传文件 → 规整列名 → 取最后窗口归一化序列 → LSTM 推理 → 构造统计特征 → RF 推理 → 健康评估 → 写入 SQLite → 组装趋势数据返回。

### 4.3 数据库实现

SQLite（`backend/database.py`），两张表：
- `predictions`：预测记录（时间、设备、已用循环、LSTM RUL、RF RUL、健康等级、建议）；
- `units`：训练集单元信息（单元号、最大循环、平均 RUL）。

### 4.4 各算法模块实现

| 模块 | 文件 | 关键实现 |
|---|---|---|
| 特征工程 | `feature_engineering.py` | 相关系数筛选、滑窗序列/统计特征、归一化、短序列补齐 |
| LSTM | `lstm_model.py` | RulLSTM 网络、训练循环、模型保存/加载/推理 |
| 随机森林 | `ml_baseline.py` | 训练、joblib 持久化、推理 |
| 健康评估 | `health_eval.py` | RUL→等级→建议映射 |

## 5 测试与集成调试

### 5.1 测试方案

pytest 自动化测试（`tests/`），三个测试文件：

| 文件 | 覆盖 |
|---|---|
| test_feature_engineering.py | 数据加载、RUL 计算、传感器筛选、窗口形状、短序列补齐 |
| test_model.py | LSTM 前向传播、模型推理、RF 推理 |
| test_api.py | 健康检查、页面、预测接口（样例数据）、空文件、历史接口 |

### 5.2 测试结果

全部用例通过（模型未训练时相关用例自动跳过，保证测试可随时运行）。

### 5.3 模型评估

| 模型 | 测试集 RMSE |
|---|---|
| LSTM（本设计） | 15.95 |
| 随机森林基线 | 48.90 |

LSTM 优于随机森林基线约 67%，验证了时序建模的显著优势。（注：C-MAPSS 官方评测采用非对称打分函数，本设计为便于对比统一使用 RMSE。）

### 5.4 集成调试

- 一键启动脚本 `start.bat`：自动建环境→预处理→训练→启动服务；
- 端到端验证：上传 `data/sample_upload.csv`（5 号测试发动机 98 个循环）可完整走通"上传→预测→展示→入库→历史查询"流程；
- 预测响应时间 < 1 秒（CPU）。

## 6 AI 使用披露（vibe coding 过程）

### 6.1 所用工具

本项目全程使用 **豆包 AI 编程助手** 进行 vibe coding 开发，用于代码生成、脚本编写、文档框架梳理与调试辅助；对比调研了 Trae、Deepseek Harness、Qwen Code 等工具（详见《学习笔记.md》）。

### 6.2 关键 prompt 策略

1. **任务拆解**：按"特征工程→模型→后端→前端→测试"分模块下达任务，每次只让 AI 完成一个可验收的单元；
2. **约束说明**：明确指定技术栈（PyTorch LSTM、FastAPI、SQLite）、输入输出形状（batch, window, n_sensor）与文件路径；
3. **验收标准**：要求函数返回形状正确、接口返回指定 JSON 字段、测试全部通过才验收；
4. **上下文工程**：修改前要求 AI 先读相关文件；关键对话保存至 `prompt/` 目录备份。

### 6.3 AI 出错案例及纠正过程

| 案例 | 错误表现 | 纠正过程 |
|---|---|---|
| 函数参数顺序错误 | `last_window_for_unit` 生成时参数顺序（scaler 与 window）与调用处不一致，运行时 TypeError | 通过最小复现定位调用处与定义处参数顺序不一致，统一签名后重跑预处理 |
| 环境依赖冲突 | Anaconda 基础环境 pandas/numexpr 等包与 NumPy 2.x 不兼容，import 即报错 | 排查后判定为基础环境版本混装，重建干净虚拟环境并分源安装依赖（PyTorch CPU 源与 PyPI 分开） |
| 测试维度断言错误 | 随机森林输入维度断言写法冗余 | 人工审查测试代码，简化并修正断言 |

以上错误均通过"最小复现 + 缩小改动"策略修复，未影响交付质量。

## 7 总结与展望

### 7.1 工作总结

本设计完成了从选题、数据准备、算法开发到 B/S 系统集成的完整课程设计闭环：
- 覆盖 4 个课程技术方向（特征工程、机器学习、深度学习 LSTM、健康评估），均在系统中承担实际功能；
- 实现了完整 B/S 架构与自动化测试，达到可现场演示状态；
- 全程 git 管理（小步提交），AI 使用过程留档可追溯。

### 7.2 不足与展望

- **模型精度**：LSTM 测试 RMSE 15.95，已达文献主流水平，仍可通过更大窗口、注意力机制、多工况数据（FD002-FD004）进一步优化；
- **功能扩展**：可增加多设备批量预测、预测结果导出、基于预测的维护工单自动生成；
- **工程化**：可引入 Docker 容器化部署、模型版本管理（MLflow）等工程能力。
